# 衣序真实研究与试用计划

状态：尚未开展。以下是招募与记录模板，不是已获得的用户证据。人数与时长都是计划目标，可按实际完成情况调整。

## 访谈

优先招募5至8位能真实描述选衣经历的人，至少覆盖通勤与校园场景。先了解最近一次事件，再展示原型，避免一开始问“你需要AI穿搭吗”。

建议提问：最近一次纠结穿什么发生在什么时候；当时要去哪里；用了什么办法；最终怎样决定；最重要的限制是什么；哪些衣物信息愿意录入、哪些难以维护；如果系统建议错误，怎样才容易发现和纠正。记录原话、行为与推断，不能把研究者总结写成用户原话。

访谈后输出需求家族、替代方案、最重要的阻力和首版取舍。5至8人适合探索，不足以估计市场渗透率或代表所有用户。

## 任务观察

建议任务：输入“18度通勤，不穿裙子，锁定白衬衫”；只修改温度并检查保留条件；排除一双鞋；制造无解并恢复；输入无法确认的材质条件；分别保存想穿计划与实际已穿记录。

开始前确认用户理解任务，但不给按钮位置。记录是否独立完成、帮助次数、错误理解、停顿位置、修改次数和结果是否可接受。界面写“符合约束”不等于用户确认条件真的满足，研究者需核对。

## 连续试用

如果前两阶段未发现阻断问题，再邀请少量用户使用数日。每天记录有无搭配需求、是否打开、收到多少可用建议、收藏/想穿/自报实际穿着、未使用原因。没有当天需求与收到建议却未采纳是不同状态。保留未反馈记录，不能只统计愿意回复的人。

“实际穿着”是用户自报，不是系统核实；不强制用户上传私人照片。记录到作品集时去除姓名、联系方式与具体生活日程。

使用本目录CSV/Markdown模板。保存参与者去标识ID和日期，不填虚拟反馈。每轮复盘按“观察到什么—认为原因是什么—改了什么—如何复验”编写。任何简历数字应能回溯到这些记录和明确分母。
