# 衣序评测方法与证据边界

## 当前完成的范围

`eval/cases.jsonl` 包含37条人工构造的开发与工程回归题，使用 `eval/fixtures.json` 中独立构造的12件示例衣物。25题预标可满足、11题预标不可满足，1题材质条件需要澄清。每题有来源、分层、预期状态和可满足性标签；部分题还预标解析字段与输出约束。这些题已参与开发，不能再称为独立保留测试或真实需求。

规则运行直接调用产品核心产生输出。判分由 `eval/evaluator.js` 完成，不导入产品的 `checkOutfit`，也不信任返回的 `pass/checks/score`。它依据题目的人工预标、独立衣橱查表和返回ID检查完整性、锁定、排除、颜色及裙裤要求。该独立性减少了复用同一个函数产生一致错误的风险；仍不能替代人工核验标注和未见需求。

2026年11月8日首轮真实混合策略运行37题，34题符合预标期待，37题实际调用模型，0降级、0执行错误；本机经HTTP端到端耗时中位数2880.93ms、P95为3479.14ms。D25、D27将缺下装/空衣橱的预标冲突返回为澄清；D28将低温正式场合软偏好变成补衣前提，也返回澄清。三题都未输出违规组合，但没有符合预标的状态策略。

这轮不支持模型优于规则的结论，规则同批开发题为37/37。当前“错误冲突”统计只计预标可行却返回`conflict`，不会捕捉返回`clarify`的不必要澄清；因此0错误冲突不等于没有错误拒答。这一指标边界在解读时必须同时查看逐题状态与失败明细，不能利用分类缝隙隐去3个失败。原始结果不因后续讨论而重写。

之后修复了澄清门控，并在 `eval/results/clarification-fix/` 单独保存D25、D27、D28真实定向复验：3/3符合预标，实际模型执行3题、0降级、0执行错误；端到端中位数1063.38ms、P95为2133.57ms。该批只有已知失败题，不能替代修复后全量37题复测或独立保留测试。首轮34/37照常保留，两个批次不拼成“模型全量37/37”。

## 固定分母与错误定义

每个请求都进入本次固定分母，执行错误也不会移除。预标可满足的题若返回冲突，记错误冲突；预标不可满足的题若返回成功，记错误成功。系统自报 `conflict` 不能改变标签或从分母删除。

输出符合预标期待，要求状态、已标解析字段、独立约束、结果完整性和必要提示均通过。无解需要具体原因，不能把违反条件的组合当作成功结果。近期少重复是软偏好，不参与硬约束通过率；明确排除才会禁止某件单品。

这批题覆盖开发场景，并未完整评估所有请求解析、单品相关性、解释事实与用户审美。开发回归37/37不应写成“AI准确率100%”。应写“37条人工构造开发回归用例符合预标期待”，同时披露数据属性。

## 运行与审计

```text
node eval/run.js --version rule
node eval/run.js --version hybrid --base-url http://127.0.0.1:5173
node eval/run.js --version direct --base-url http://127.0.0.1:5173
```

可用 `--max-cases 1` 做调用连通性检查，或 `--out-dir` 保存另一轮结果。运行器会在本机生成 `eval/results/{version}-results.json`、`{version}-results.csv`、`{version}-summary.json`和`{version}-report.md`；默认同名文件会更新，需比较的轮次应另行归档。公开仓库包含人工题库、独立评测器、运行器与选定分批汇总；历史逐题模型响应和原始请求日志仅在本地留存，不提供公开下载。

本机生成的逐题JSON保留实际响应、预期、逐项判分、请求版本、实际模式、降级、耗时和API原始usage。运行清单记录时间、Node版本、题库/衣橱/核心SHA256。未配置模型、请求失败或回退规则时不计作模型执行；混合策略部分阶段成功但全局回退时也不计完整模型执行，原始`meta.modelStages`仍保存。模型分母为0时没有模型效果结论，也不能拿回退结果作为AI版成绩。原始usage没有可靠价格配置时不换算费用。时延统计采用runner端端到端时间，另存API的`meta.elapsedMs`供诊断，不混算。重新运行得到新一轮记录，不保证模型历史输出一致。

最终工程测试为105/105，通过不等于模型泛化质量。新增 `eval/weather-cases.json` 的12条人工天气任务仍为 `draft_not_run`，没有纳入上述37题，也尚未形成天气质量通过率。真实天气与公网AI链路的单次成功另见仓库中的天气实施记录。

## 检索相关性与排序

当前没有完整相关性真值，因此不报告 Recall 或 NDCG。未来以查询—单品为单位独立标注：0无关或违反明确硬条件；1已有充分证据支持但仅弱相关；2有证据满足主要需求；3同时较好覆盖已表达偏好。关键证据缺失、无法判断时独立标记为 `U`（未知），不标成1，也不当作正相关。标注口径先做示例校准，再由另一位评审复核部分样本；模型可辅助提议，不能自产自评充当最终真值。

正式计算前固定二值相关阈值，例如等级≥2，并固定分级增益表；不可看过结果后改阈值追求提升。`U`需补证、复核，或将受影响查询列为真值不完整并另报数量。不能把`U`当作0或正相关后宣称全量Recall/NDCG；也不能静默删除系统返回的未知项来抬高指标。策略任务单独评价是否澄清、说明未知和拒绝虚构。

Recall@K的分母必须是在定义语料内的全部相关单品；只看返回结果不知道漏了多少。正式报告可对一个受控的完整衣橱/商品库逐项标注。若仅有多个系统的候选并集，应披露候选池范围，不将其当全库召回。NDCG需要固定分级标签和理想排序；不能默认未标注候选全为0。没有相关结果的题单独评价，不强算分母为0的指标。

搭配组合相关性与单品检索相关性分开，组合满足硬条件不等于单品排序好。搜索结果解释中的事实支持也需要额外核验，不可用“有链接/有理由”替代。

## 版本对比和人工盲评

规则基线、混合策略与直接模型使用相同衣橱、任务和展示数量。对候选重排增益进行比较时保持候选池一致；比较候选生成时单独说明策略差异。保存模型、参数、Prompt/代码版本、实际调用与降级。不要同时换模型、改检索再把提升归因于一个模块。

先隐藏方法和理由只比较组合，允许胜/平/负/都不可用；再在同一组合下单独评价解释。展示顺序随机，重复候选应标记而非当独立差异。随机基线只能作低参照，不能替代有竞争力的规则策略。

一致性指标要求多位评审对相同题独立评分。每题只有1人评分时不计算κ。两位评审评有序等级可按事先规则计算加权κ，配对偏好可以直接报告一致/分歧数。小样本先保留原始意见，不必为了统计名词增加无意义指标。

## 用户试用与解释限度

任务完成、收藏、想穿、自报实际穿着各自定义分母；生成套数不是用户数。试用反馈支持问题发现与迭代，不直接证明业务增长。非随机前后对比不得称A/B实验。小样本的偏好结果应同时给出人数、任务数和胜平负，不能把同一人重复评题视为大量独立用户。

本机一次回归的延迟不代表手机4G或线上P95；模型回退时不能声称模型延迟。后续性能报告应明确设备、网络、部署区域、预热、并发和有效样本。
