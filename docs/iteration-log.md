# 衣序开发迭代与失败分析

本记录说明已经观察到的问题、工程改动与现有证据。开发回归与自动化测试不能替代独立保留集或真实用户研究。没有虚构迭代提升比例。

## 模型输出截断与联调

早期联调使用900 tokens输出预算，模型默认thinking模式下出现输出被截断，无法取得完整JSON。该现象是当前服务和配置下的观察，不代表所有模型都需要相同参数。

随后对所用服务禁用thinking，并将输出预算调整为1600 tokens；适配层识别`finish_reason=length`并明确返回截断降级，避免把不完整JSON冒充成功。禁用thinking参数只在服务兼容时发送，其他服务仍需按实际接口核实。

调整后完成首轮真实混合策略37题调用，0降级、0执行错误；其中34题符合预标期待，另3题为产品策略问题而非格式或网络失败。没有将一次连通成功解释成模型整体质量提升。

| 问题 | 已实施的工程处理 | 可核对证据 |

| 只看Top K就判无解 | 在受限组合空间完整校验后再截取；超过枚举上限澄清而非谎称无解 | core枚举逻辑与feasible/full space用例 |

| 多轮修改丢失条件或重置后恢复旧锁定 | 保留未修改字段；重置清空上下文；模型更新需当前原文证据 | core multi-turn与service reset/evidence用例 |
