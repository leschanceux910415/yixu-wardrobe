## 独立判分与固定分母

产品核心负责产生规则结果。`eval/evaluator.js`通过预标条件、独立衣橱查表与返回ID判分，检查完整性、锁定、排除、颜色和裙裤要求。

每个请求进入固定分母，执行错误同样保留。输出符合预标要求需同时满足状态、已标解析字段、完整组合、独立约束和必要提示。错误按以下口径记录：

- 预标可满足而返回 `conflict`：错误冲突。
- 预标不可满足而返回 `ok`：错误成功。
- 预标可满足而返回多余 `clarify`：不必要澄清，结合逐题失败记录分析。
- 模型异常或额度拦截：保留实际回退、错误及调用阶段。

当前汇总的 `falseConflicts`覆盖第一种错误；首轮3题澄清问题保留在失败明细与34/37总通过数中。后续指标将单列不必要澄清。近期少重复属于软偏好；显式排除进入硬约束检查。

模型有效成绩统计实际完成模型流程且无整体回退的任务；规则结果和降级路径另列。无解与澄清路径根据实际阶段统计调用量。

## 运行与归档

```text
node eval/run.js --version rule
node eval/run.js --version hybrid --base-url http://127.0.0.1:5173
node eval/run.js --version direct --base-url http://127.0.0.1:5173
```

`--max-cases 1`用于连通性检查，`--out-dir`用于归档新批次。运行器生成逐题JSON、CSV、summary与report；默认同名文件会更新。模型评测需先启动服务并配置模型，调用消耗实际服务额度。

逐题记录包含预期、实际响应、逐项判分、请求版本、实际模式、回退、耗时和usage。运行清单保存时间、Node版本与题库、衣橱、评测器、代码的SHA256。runner墙钟时间用于端到端统计，API的 `meta.elapsedMs`用于服务诊断；usage结合实际服务单价计算费用。

公开仓库提供人工题库、独立评测器、运行器与分批汇总，历史逐题响应和原始请求日志在本地归档。重新执行时生成独立批次，并记录当前模型与参数。

## 检索相关性标注

Recall与NDCG的准备工作是建立完整相关性真值。计划按查询—单品标注：0为无关或违反硬条件，1为有证据支持的弱相关，2为满足主要需求，3为同时较好覆盖偏好。证据缺失时标记 `U`，补证或复核后再进入完整真值统计；报告同时列出真值不完整的查询数量。

正式比较前固定二值相关阈值与分级增益表，例如等级≥2为相关。Recall@K使用定义语料内全部相关单品作分母；NDCG使用固定等级与理想排序。候选并集标注需记录覆盖范围，无相关结果任务单列。组合约束、单品相关性与解释事实性分别评价。

## 版本比较与人工盲评计划

规则、混合策略和直接模型使用相同衣橱、任务与展示数量。重排比较固定候选池，候选生成比较单独记录策略。每批保存模型、参数、Prompt、代码版本、实际阶段与回退。

盲评计划先隐藏方法和解释，只比较组合，选项为胜、平、负、都不可用；随后固定组合评价解释。展示顺序随机，重复候选单列。计划抽取部分任务由两位评审独立评分，记录一致与分歧；有序等级可按预设规则计算加权κ。

天气对照采用A单温度规则、B冻结天气＋规则、C相同天气/条件/候选池＋模型重排。A与B比较新增天气信息，B与C比较模型重排贡献。

## 用户与性能评价

任务完成、收藏、想穿、自报已穿分别定义分母。试用记录保存人数、任务数、帮助次数、偏好胜平负与未反馈状态。前后任务观察用于发现问题，随机分组实验用于后续效果归因。

性能批次记录设备、网络、部署区域、预热、并发、有效样本、端到端时延、usage、失败与回退。后续将结合真实用户任务、未见测试与盲评，评价可用性、偏好及模型增量。
